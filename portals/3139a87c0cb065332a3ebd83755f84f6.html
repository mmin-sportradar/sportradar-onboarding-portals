AUTHENTICATION & NETWORK

Your unique Client ID (ffffffffffffffffffffffffffff0001) is embedded in the widget loader URL and is what authorises widget rendering on your site. There is no separate API key to manage for widget display — keep the loader URL exactly as provided.

Loader URL: https://widgets.sir.sportradar.com/ffffffffffffffffffffffffffff0001/widgetloader

Network requirements. Widgets load assets and data from Sportradar domains. Make sure *.sir.sportradar.com, widgets.sir.sportradar.com, fonts.googleapis.com, fonts.gstatic.com are reachable from your site and not blocked by your CSP, firewall, or ad-blockers.

HOW TO INTEGRATE
ADDITIONAL DOCUMENTATION

Implementation checklist

  1. Copy the three files (preview.html, script.js, theme.css) provided below — your Client ID is already embedded.
  2. Or open “Get Code” on the demo page, where one exists, to download them directly for your widget and sport.
  3. Add script.js and theme.css to your page and include the #sr-widget container.
  4. Set the required parameters (e.g. matchId/seasonId) to your real identifiers.
  5. Allow-list the Sportradar domains in your CSP/firewall.
  6. Test on a staging page and confirm the widget renders.
  7. Send us your production domain(s) and a test URL to verify.
  8. Go live.

Common mistakes

  • Leaving "sportradar" in the loader URL instead of your Client ID.
  • Using a placeholder matchId instead of a real identifier.
  • Content-Security-Policy blocking the Sportradar script or data domains.
  • Loading the script before the target container div exists in the DOM.
  • Embedding multiple widgets into the same #sr-widget element id.

Troubleshooting

SymptomFix

FAQ

Where do I put my Client ID?

It replaces "sportradar" in the loader URL: https://widgets.sir.sportradar.com/ffffffffffffffffffffffffffff0001/widgetloader

How do I get a matchId / seasonId?

See the widgets documentation: https://apidocs.sportradar.com/resources/widgets

Do I need an API key?

No separate key is needed for widget rendering — the Client ID in the loader URL is sufficient.

Yes — each widget supports configuration properties documented on its widget page.
